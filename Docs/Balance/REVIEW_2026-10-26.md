# 전체 밸런스 재점검 및 변경 제안

작성: 2026-10-26. 기준: **직업/E Lv5, R Lv10, 5레벨마다 잡몹 수 증가를 적용한 현재 작업본**.

이 문서는 현재 구현과 개선 제안을 구분한다. 아래 **제안 수치는 미적용**이며 이번 작업은 조사·계산·문서 정리다. 이전의 E 10~15분/R 45~55분 목표와 옛 `CURRENT_VALUES.md`를 현재 구현으로 해석하지 않는다.

## 1. 결론과 적용 우선순위

현재는 직업과 스킬을 앞당겼지만, **성장 선택의 처리·효율, 지역별 경험치 공급 차이, Lv10 이후 전투 변화 부족**이 남아 있다. 잡몹 수 증가를 넣은 상태에서 경험치까지 일괄 올리면 성장 속도와 화면 압박이 함께 치솟을 수 있다.

권고 순서는 다음과 같다.

| 우선순위 | 변경안 | 이유 |
| --- | --- | --- |
| P0 | 능력치 선택의 대기·표시·확정 상태를 저장하고, 여러 경험치 지급이 들어와도 선택 요청을 순서대로 처리 | 같은 레벨인데 실제 받은 성장 횟수가 달라지는 문제부터 해결 |
| P0 | 현재 성장 UI에 직업별 선택 보장 정책을 연결하고, Lv5 이전에는 마력 후보 제외 | 설정과 화면이 다르고, 초반 마력은 즉시 사용할 스킬이 없음 |
| P0 | Lv5/E·Lv10/R 및 레벨별 잡몹 수는 사용자 지정값 유지. 요구 EXP와 몬스터 EXP는 우선 유지 | 최근 스폰 변경의 효과를 측정할 기준 필요 |
| P1 | 공속 +5→+8%p, 마력 +8→+12, 사거리 +3→+6%p 시험 | 작은 성장 선택의 체감 개선. 공격 +0.25·HP +1·이동 +3%p는 우선 유지 |
| P1 | 지역별 엘리트 보상 접근성과 반복 엘리트 등록 통일 | 현재 장만 반복 엘리트 규칙이 등록되어 있음 |
| P1 | 약한 DoT가 강한 DoT를 덮어쓰지 않도록 중독·출혈 갱신 규칙 수정 | 아이템과 직업 스킬을 조합했는데 피해가 내려갈 수 있음 |
| P2 | Lv15/20/25에 기존 스킬·아이템의 변형 선택 추가 | R 이후에는 새 스킬 해금이 없어 긴 캠페인에서 다시 단조로워질 수 있음 |
| 조건부 | 후반 요구 EXP 완화, 보스 HP 감소, 전체 플레이 시간 단축 | 실제 성장 간격·보스 실효 DPS를 확인한 뒤 조정 |

추천 첫 비교 버전은 **P0 수정 + 성장 선택 세 항목 상향**이다. 이때 몬스터 EXP·HP·스폰 수를 동시에 조정하지 않아 효과를 구분한다.

## 2. 조사 범위와 근거

- Normal/Hard 성장·난이도 자산, Hub의 공격/스킬 설정, 몬스터 정의 30개, 지역별 스폰 규칙, 보상·회복·최종 보스 설정을 확인했다.
- 레벨업 화면, 경험치 지급, 저장 복원, 아이템 효과와 스킬 실행 경로를 읽었다. 아이템 60개 정의·설명을 확인하고 주요 성장/상태이상 상호작용을 점검했다. 3개 조합 34,220가지의 실전 검증을 수행한 것은 아니다.
- [전체 계산표](REVIEW_TABLES_2026-10-26.md)는 1~30레벨 EXP, 처치량 환산, 시간 민감도, 몬스터 표를 담는다. [생성 스크립트](../../Tools/BalanceChecks/review_balance.py)로 재생성할 수 있다.
- [실제 C# 탐침 결과](REVIEW_PROBE_2026-10-26.json)는 성장 이벤트·저장 복원·몬스터 EXP 계산을 확인한 결과다. 작은 엔진 대체 API로 게임 C#을 실행했으며 Unity UI/물리 실행은 아니다.
- 탐침 재현: 저장소 루트에서 `python Tools/BalanceChecks/validate_assets.py` 후 `dotnet run --project Tools/BalanceReview` 실행. [탐침 코드](../../Tools/BalanceReview/Program.cs)는 관찰 결과를 기록하며 버그가 수정되면 결과도 달라진다.
- [원본 해시](REVIEW_SOURCE_HASHES_2026-10-26.json)에 126개 파일의 확인 시점 SHA-256을 기록했다. 이후 게임 코드를 바꾸면 계산과 판단을 다시 확인한다.
- `Logs/CampaignBalance`에 이번 20분 플레이를 분석할 `current-play-report.json`은 없었다. 분당 처치 수·클리어 시간·실전 DPS는 **측정값이 아닌 가정 또는 검증 목표**다.
- 기존 검사 174개 자산 / 1,687개 C# 검사는 통과했다. 이 통과가 아래에서 새로 발견한 성장 선택 복원 문제까지 검증했다는 뜻은 아니다.

## 3. 레벨업: 현재 실제로 주는 성장

### 3.1 설정과 화면의 차이

현재 Hub는 GUID로 `LevelUpStackChoiceUI`를 연결하고 `disableBuiltInLevelUpUI=1`이다. 씬의 클래스 표시 문자열은 예전 `StackChoice`이지만 스크립트 GUID는 현재 파일과 일치한다.

이 화면은 공격력·공속·사거리·마력·이동·HP **6개 중 무작위 5개를 보여주고 하나를 선택**한다. 공속과 사거리는 별개의 선택이다. `LevelUpManager.GetRandomChoices()`에 있는 직업별 핵심 스탯 보장 및 공속/사거리 묶음은 이 화면이 사용하지 않는다.

따라서 `jobBasedChoiceStartLevel=6`이 저장되어 있어도 **현재 주력 화면에서 Lv6 이후 직업별 후보가 보장된다고 말할 수 없다.** 앞선 적용 설명을 이 내용으로 정정한다.

근거: [성장 화면](../../Assets/_Project/Scripts/UI/LevelUp/LevelUpStackChoiceUI.cs), [레거시 후보 생성](../../Assets/_Project/Scripts/Gameplay/Player/Progression/LevelUpManager.cs), [Hub](../../Assets/_Project/Scenes/Hub.unity).

### 3.2 능력치별 효과와 제안

아이템 없는 기본값은 HP10, 이동10, 공격1, 공속1, 사거리1, 마력1, 쿨감0이다. 퍼센트 성장은 현재 최종값에 매번 곱하는 복리가 아니라 같은 종류끼리 합산한다. 공통 계산은 `(기본값 + Flat 합) × (1 + PercentAdd 합) × PercentMultiply 곱`이다.

| 선택 | 현재 1회 | 실제 의미 | 권고 시험값 | 판단 |
| --- | --- | --- | --- | --- |
| 공격력 | +0.25 | 공격1일 때 평타 피해 +25%, 공격4일 때 +6.25% | **+0.25 유지** | 여전히 초반 평타 성장의 큰 보상. 추가 하향보다 다른 선택을 보강 |
| 공격속도 | +5%p | 기본 공속1→1.05. 평타 쿨 0.75→0.714초 | **+8%p** | 한 번 선택 후 차이를 조금 더 분명히 함. 스킬 쿨타임은 줄지 않음 |
| 사거리 | +3%p | 평타 거리/근접 판정 확대. 스킬 범위 전체를 키우는 효과 아님 | **+6%p** | 공속과 분리된 한 번의 선택치로는 현재 보상이 작음 |
| 마력 | +8 | 스킬 배율1.01→1.09, 스킬 피해 상대 +7.92% | **+12** | 스킬 투자 가치를 높임. 배율1.01→1.13, 상대 +11.88% |
| 이동속도 | +3%p | 기본10 기준 +0.3. 10회 선택 시13 | **+3%p 유지** | 회피·거리 유지·탐색에 모두 영향. 먼저 전투 밀도 조정 결과 확인 |
| 최대 HP | +1, HP1 회복 | 하트 반 칸, 최대 HP와 회복을 같이 제공 | **유지** | 일관된 생존 선택. 실제 회복이 필요한 시점에 가치가 커짐 |

위 시험값은 검증된 최종값이 아니다. 성장 확률·피격 빈도·아이템 배율에 따라 다시 조정한다. 마력은 모든 직업의 E/R에 적용되고, 공격력은 공통 스킬 피해 공식에 직접 들어가지 않는다.

기본 공격력1에서 HP6 적은 평타6회, 공격 한 번 선택 후1.25에서는5회가 필요하다. 반면 공속 한 번은 간격만 약4.76% 줄인다. 즉 레벨업 숫자가 올라가도 처치에 필요한 공격 횟수가 그대로인 선택이 많다. 공격력만 강하게 느껴지는 이유가 있다.

공속/마력의 증가율은 해당 공격 부분의 증가율이다. 예를 들어 전체 피해의 40%가 평타라면 평타 +25%는 전체 약+10%, 스킬 비중60%에서 스킬 +11.88%는 전체 약+7.13%다. 이를 동일한 전체 DPS 증가로 표기하면 안 된다.

### 3.3 선택 후보와 성장 횟수

**권고 후보 정책:** Lv2~4는 마력을 제외한 5개 표시, Lv6부터 전사 공격력·궁수 공속·마법사 마력을 최소 한 자리 보장하고 나머지를 섞는다. UI를 바꿀 경우 기존 `selectionHistory`에서 공속과 사거리가 레거시 항목 하나로 기록되는 매핑도 함께 정리한다.

현재 순차적으로 Lv5에 도달하면 `OnLevelUp` 3회, `OnJobSelect` 1회가 나온다. **Lv5에서 일반 스탯 선택이 직업 선택으로 대체**된다. 이를 유지하면 정상적으로 모든 선택을 완료한 경우 Lv10까지 8회, Lv20까지18회, Lv30까지28회다. 29회 성장했다고 가정한 종결 빌드는 한 선택만큼 과대평가한다.

추천 정책은 “레벨업마다 능력치 선택 1회, 전직은 추가 선택”으로 명확히 만드는 것이다. 그러면 Lv30까지29회다. 다만 Lv5에는 E와 시작 변이까지 함께 생기므로 능력치 선택을 생략하는 기존 정책을 의도적으로 유지할 수도 있다. 이 항목은 **무조건 버그로 단정하지 않고 보상 정책을 확정할 사항**이다.

### 3.4 수치보다 먼저 고칠 성장 보존 문제

실제 `LevelUpManager`를 실행한 탐침에서 다음을 확인했다.

| 재현 | 확인 결과 | 영향/권고 |
| --- | --- | --- |
| Lv1에서 EXP150 지급 → Lv4, 선택 한 번만 알림 → 즉시 저장/복원 | 복원 전 대기 선택 있음, 복원 후 없음 | `pendingLevelUps`와 현재 표시 중인 미확정 선택을 저장해야 함 |
| 능력치를 선택하지 않은 상태에서 EXP30, 이어 EXP50 지급 | 능력치 선택 이벤트2회, 대기 플래그 없음 | 현재 UI는 다시 열 때 후보를 지우므로 같은 프레임 다중 처치 등의 중복 요청으로 선택이 교체될 위험 |

저장 모델은 레벨·경험치·확정 모디파이어를 저장하지만 대기 선택은 저장하지 않으며 `RestoreProgress`에서 대기를0으로 만든다. 직업 선택 중 보관된 **경험치**가 보존되는 것과 미확정 **능력치 선택권**이 보존되는 것은 별개다.

수정안: 대기 보상 큐를 단일 진입점으로 관리하고, UI가 열려 있으면 추가 요청을 큐에 적재한다. 저장 시 표시 중인 선택까지 포함하여 수령 여부와 원자적으로 기록한다. 기존 세이브는 Lv5 정책·생체 도박0배·모디파이어 기록 등을 고려해 마이그레이션해야 하며, 단순히 `레벨−선택이력수`를 전부 재지급하면 중복 보상이 생길 수 있다.

## 4. 경험치: 해금은 유지하고 공급량부터 측정

현재 요구량은 `Q(L)=30+20×(L−1)`, Lv1에서 LvL까지 누적은 `C(L)=10×(L²−1)`이다.

| 도달 | 누적 EXP | 일반몹 EXP10~15만으로 환산 |
| --- | --- | --- |
| Lv5 직업/E | 240 | 16~24마리 |
| Lv10 R | 990 | 66~99마리 |
| Lv15 | 2,240 | 150~224마리 |
| Lv20 | 3,990 | 266~399마리 |
| Lv25 | 6,240 | 416~624마리 |
| Lv30 | 8,990 | 600~899마리 |

이 환산에는 엘리트·보스와 후반 EXP 배율이 없다. 실제 캠페인 처치 수와 같다고 해석하지 않는다.

### 4.1 초반2배 설정을 경험치 예산에 넣으면 안 됨

일반 적은 `GrantExp → AddResolvedEnemyKillExp`, 지역 보스도 `AddResolvedEnemyKillExp` 경로다. 이미 몬스터 난이도/진행도 보상을 계산한 값을 지급하므로 `earlyExpGainMultiplier=2`가 다시 적용되지 않는다. `AddExp`에는 구간 배율이 있지만 이번 검색에서 실제 게임 코드의 `LevelUpManager.AddExp(...)` 호출은 찾지 못했다.

현재 직업 선택 레벨5는 `earlyLevelUpperBound=9` 안에 있어 `GetExpGainMultiplier`의 초반 분기가 직업 대기 분기보다 먼저 실행된다. 향후 `AddExp` 호출을 추가할 경우 혼동할 지점이다. **처치 경험치에는 배율을 중복 적용하지 않고, 이벤트 보상도 최종 지급량인지 원본량인지 명확히 구분**할 것을 권한다.

### 4.2 스폰이 늘어난 지금 경험치를 함께 올리지 않는 이유

스포너별 평균 목표는 1.5→2.5→3.5→4.5→5.5→6.5마리다. 최저 구간 대비 최고 구간은 약4.33배다. 같은 활성 스포너 수·동선을 가정하면 더 많은 적이 경험치와 처치 발동 아이템을 공급한다.

평균 EXP12인 적을 분당8마리 잡으면 잡몹만으로 Lv5는2.5분, Lv10은10.31분이다. 분당12마리면 각각1.67분/6.88분이다. 옛 예산의 분당4.4마리라면 R은18.75분이라 여전히 늦다. **해금 레벨을 낮췄다는 사실만으로 R이 6~10분에 보장되지는 않는다.**

목표는 신규 플레이에서 직업/E 약2~4분, R 약6~10분으로 두되, 먼저 실제 분당 처치와 엘리트 보상 유입을 측정한다. 느린 원인이 빈 이동 구간이면 스폰 위치/동선을, 적이 질기면 처치 시간을 조정한다. 몬스터 한 마리 EXP를 올리는 것은 그 다음이다.

### 4.3 후반 요구량의 조건부 대안

기본 권고는 현재 곡선 유지다. Lv10 이후 **싸우고 있는데도 레벨업 간격 중앙값이120초를 넘는 구간이 반복**되고, 교전 접근성/성장 선택 문제가 해결된 뒤에도 느리면 다음 곡선을 비교한다.

- Lv1~10 도달 요구량 유지.
- 현재 레벨10 이상에서 `Q(L)=210+16×(L−10)`.
- Lv20 누적3,990→3,810, Lv30 누적8,990→8,230. 종결 요구량 약8.45% 감소.
- 해금5/10과 잡몹10~15 EXP를 보존해 변경 범위를 제한한다.

반대로 Lv20/30이 너무 빨리 오면 경험치를 먼저 낮추기보다 활성 스포너 수·반복 엘리트 추가 보상·탐색 경로를 확인한다. 플레이어 레벨이 오르면 스폰 수가 늘어나는 양의 피드백이 있기 때문이다.

### 4.4 지역 보상 예산

첫 네 지역의 보스 EXP 합계는1,190, 전용 엘리트2마리씩 모두 잡으면970, 고정 합계는2,160이다. 나머지6,830은 일반몹과 반복 엘리트 등에서 얻어야 Lv30에 도달한다. 두 보상을 일반몹 예산에 다시 더해 중복 계산하면 안 된다.

초기 지역별 EXP 예산을 시험할 때는 **총 보상 기준** 약1,400 / 2,100 / 2,500 / 3,000을 기준선으로 삼을 수 있다. 합계9,000으로 Lv30 근처이며 종료 누적 레벨은 대략11 /18 /24 /30이다. 이는 목표이지 강제 지급이나 고정 처치 수가 아니다. 스폰 변경 후 실제 조기 만렙 여부를 반드시 확인한다.

## 5. 몬스터 수·지역·엘리트·회복의 연결

### 5.1 잡몹은 사용자 지정 구간을 유지

1~5:1~2, 6~10:2~3, 11~15:3~4, 16~20:4~5, 21~25:5~6, 26~30:6~7마리다. 스포너별 목표이며 맵 전체 상한이 아니다. 추가 생성은 현재의 거리·재생성 대기·화면 밖 조건을 따른다. 새 스포너의 첫 생성은 별도 경로이므로 모든 상황에서 화면 내 생성이 금지된다고 설명하면 안 된다.

개체 수가 늘어도 적의 HP는 플레이어 레벨에 비례해 오르지 않고, 지역 클리어 진행도에 따라1/1.15/1.35/1.6배가 된다. 하지만 HP6 적 무리의 총 HP를 비교하면 최초 평균9에서 후반62.4까지 약6.93배다. 6레벨 진입 때 평균 무리 수가1.5→2.5로 약66.7% 늘어나는 첫 경계도 확인해야 한다.

**검증할 위험:** 늘어난 수가 경험치 공급보다 포위·투사체 압박으로 작용할 수 있다. 특히 사거리·단일 타깃에 집중한 빌드는 광역 스킬 빌드와 체감이 달라진다. 가까운 여러 스포너가 겹치는 상황을 계측하고, 과밀하면 스포너 활성 반경/배치 간격을 먼저 조정한다. 생존 중인 적을 강제로 지우는 방식은 피한다.

### 5.2 지역별 실제 공급 구조가 다름

- 장: 일반 규칙6종, 반복 엘리트 `Granuloma/Antibody` 2종 등록.
- 간·폐·위: 일반 규칙3종씩, 반복 엘리트 등록 없음.
- 네 지역 모두 `normalKillsPerElite=40`이라는 값은 있지만, `EliteSpawner`는 등록 엘리트가 없으면 처치 누적도 수행하지 않는다.
- 맵당 전용 엘리트2마리는 별도 시스템이다. 위 사실이 간·폐·위에 엘리트가 전혀 없다는 뜻은 아니다.

권고: 각 지역의 전용 엘리트 첫 만남을 약3~5분 동선에 보이게 배치한다. 반복 엘리트는 네 지역 모두 별도 반복용 규칙을 등록하고40킬 간격에서 비교하되, 생존 중인 반복 엘리트 상한1마리와 대기열 처리를 함께 설계한다. 전용 엘리트의 저장 ID와1회 보상 규칙을 반복 소환에 재사용하면 안 된다.

장만 추가 EXP가 나오는 현 상태를 유지할 경우 다른 지역의 탐색·상자·고정 엘리트 보상으로 보정해야 한다. 동일한 종료 레벨 목표를 두고 같은 처치 수를 요구하면 지역 간 차이를 놓친다.

### 5.3 회복

현재 일반몹30/60/90킬마다 HP2, 지역당최대6이며 지역 보스 클리어 HP4다. 한 지역에서 드랍 회복6을 모두 먹고 보스 회복4도 낭비 없이 받는 경우 최대10이다. HP 성장은 별도로 +1 회복을 준다.

분당8킬이면 첫 회복3.75분,12킬이면2.5분이다. 수 증가만으로 회복 도달도 빨라진다. **기본안은30/60/90 유지**. 초반 사망이 첫 회복 전에 집중되면 총량6은 유지하면서 **20/50/80킬**로 앞당기는 대안을 시험한다. 총량과 시점을 동시에 늘리지 않는다.

### 5.4 Normal과 Hard

현재 두 프로필의 전투 배율과 성장 수치는 거의 같고, 핵심 차이는 사망 시 진행 보존 여부다. Normal 장에는 배치 밀도1.25배가 따로 있어, 같은 마릿수 규칙에서 오히려 Normal 장의 스포너가 더 많을 수 있다. 양수 `enemyMaxAlive` 배율은 새 잡몹 마릿수 계산에서는 사용하지 않는다.

노말 기준을 먼저 맞춘다. Hard를 전투 난도까지 높일 때도 경험치 감소·적 HP·공격·밀도를 한 번에 올리지 말고, 패턴 간격/적 구성 한 축부터 비교한다. 장의 배치 밀도 차이는 의도 여부를 먼저 결정해야 한다.

## 8. 잡몹·엘리트·보스 체력과 난도

| 구분 | 현재 | 1차 권고 | 실전 목표/판단 |

지역 보스 유효 DPS3이면 HP360에120초, DPS5이면 HP580에116초다. 스킬이 빨라진 현재 버전에서 보스 HP를 먼저 더 올릴 근거는 없다. 반대로 회복/무적/표적 접근 때문에 유효 DPS가 떨어지면 같은 HP라도 길어진다. 간의 회복 자세, 장/위의 전환, 폐 두 몸을 따로 확인한다.

최종전은 본체40%에서3페이즈,10%에서붕괴 시작이다. 붕괴 시 잔여HP는 최대160으로60초 내 마무리하려면 평균2.67DPS가 필요하다. 60초를 넘기면 단순 즉사가 아니라 경계/초과시간 피해가 작동한다. 기둥/본체 공유 HP를 페이즈별로 중복 합산하지 않는다.

최종전이 보통 빌드에서10분을 계속 넘고 반복 패턴이 지루하다면 **본체1,600→1,200**, 기둥180 유지 버전을 먼저 비교한다. 이 경우 본체 피해시간25% 감소, 붕괴 잔여HP120/60초=2DPS다. 적용 전 소환물/반사/패턴 대기까지 포함한 실효 DPS를 확인한다.

## 9. 성장 변화와 전체 길이

Lv10에 R까지 얻은 뒤 Lv30까지는 새로운 액티브 슬롯 해금이 없다. 3슬롯이 일찍 완성되면 교체 보상이 기존 조합을 버리는 선택으로만 느껴질 수 있다. **Lv15/20/25에 현재 장착 스킬/아이템을 강화하거나 변형하는 선택**을 제안한다. 예: 전사 출혈 처치 시 주변 전이, 궁수 관통 후 약화 폭발, 마법사 E 범위 확장 또는 R 지연 완화. 신규 효과이므로 계수·발동 상한·보스 적용은 별도 설계가 필요하다.

기존 문서는 첫 성공 약120분을 목표로 잡았다. 이 목표와 빠른 초반 전투는 분리해서 평가해야 한다. 시간을 채우기 위해 잡몹 HP나 길 찾기 시간을 늘리는 방식은 추천하지 않는다.

첫20분 시험 목표는 직업2~4분 → R6~10분 → 첫 보스 도전12~18분 → 보상 후 다음 지역 진입이다. 이것이 재밌어졌는지 먼저 확인한다. 전체120분을 유지하려면 지역 안의 새로운 전투/탐색 사건이 필요하다. 별도 대안으로 필드10~14분×4, 지역 보스1.5~3분×4, 허브3~5분, 최종6~9분이면 실패 제외55~82분이다. **전체 길이 단축은 이번에 확정·적용한 요구가 아니라 추가 기획 선택안**이다.

## 10. 다음 구현과 검증 순서

1. **성장 보존/중복 UI**: 다중 레벨업·동일 프레임 다중 처치·선택 중 저장/로드를 검증하고 보상 큐를 수정.
2. **실제 선택 화면**: 전직 전 마력 제외, 직업별 핵심 후보 보장, Lv5 일반 성장 지급 정책 확정.
3. **성장 수치 A/B**: A는 현재, B는 공속8%p/마력12/사거리6%p. 같은 직업·시드·아이템 조건으로 비교.
4. **지역 공급**: 네 지역 첫 진입에서 첫 전용 엘리트/상자까지 시간, 반복 엘리트 존재 여부 및 누적EXP 비교. 등록 통일은 보상 예산에 포함.
5. **아이템 상호작용**: 강한 DoT 뒤 약한 DoT, 근육 경련, 생체 도박 슬롯 교체, 광역 처치 연쇄를 확인.
6. **조건부 수치**: 후반 레벨업 지연이 남으면 EXP 대안, 보스 반복이 길면 HP 대안을 각각 별도 비교.

### 필요한 기록

기존 기록은 Lv10/Lv20 시각, 첫 아이템, 지역별 시간·처치·EXP, 스킬 사용 수를 남긴다. **Lv5 전직 시각을 남기지 않으며**, 현재 R은 Lv10이므로 옛 Lv20 기록을 R 해금 시각으로 해석하면 안 된다.

추가로 매 레벨 도달/선택 완료 시각, 후보·선택 스탯, 현재 표시/대기 보상 수, 전직/E/R 해금, 지역 진입 레벨, 스포너 활성 수와 반경14 이내 적 수, 최근60초 처치·획득EXP, 기본 공격/스킬별 유효 피해를 기록할 것을 권한다. 전체 세션·활성 시간·UI 대기를 구분한다.

| 지표 | 첫 비교 기준 | 벗어날 때 먼저 볼 부분 |
| --- | --- | --- |
| 첫 전직/E | 2~4분 | 분당 처치·빈 이동·초반 마력 선택 |
| R | 6~10분 | 엘리트 접근·처치시간·지역별 보상 차이 |
| Lv10 이후 성장 간격 | 중앙값60~120초 | 실제 EXP/분, 보상 큐, 해당 레벨 스폰 단계 |
| 일반 적 처치 | 2~4초 | 공격 횟수·실제 입력·무리 구성 |
| 첫 보스 전투 | 90~150초 | 실효 DPS·회복/무적·피격으로 끊기는 시간 |
| 직업 간 같은 조건의 보스 시간 | 중앙값 차이±15% 목표 | 스킬 적중·DoT 덮어쓰기·아이템 편중 |
| 공속/마력/사거리 선택 | 후보 노출 대비 선택률 및 체감 | 낮은 선택률만으로 약하다고 단정하지 말고 빌드·보유템과 함께 분석 |

최소 비교는 세 직업×같은3개 시드×A/B 각20분이다. 평균뿐 아니라 느린 플레이와 특정 지역에 집중되는 문제를 본다. 기존 세이브는 옛 성장량이 남으므로 수치 A/B는 새 게임 또는 동일한 통제 스냅샷을 사용한다. 이 문서의 목표들은 달성 여부를 확인할 기준이며 이미 검증된 결과가 아니다.
