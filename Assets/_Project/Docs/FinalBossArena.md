# 최종보스 맵 — 공통 타일맵 구현

## 사용법

- 최종보스 씬에 진입하면 남쪽 통로 하단 `(24, 4)` 셀에서 시작합니다. 폭 6칸의 직선 통로를 약 27칸 걸어 보스방 문턱을 넘으면 1페이즈와 봉인 UI가 시작됩니다. 통로에서는 적과 타워 피해 대상을 생성하지 않습니다.

- 플레이 중 F8 → **4개 맵 보스 처치 완료 (저장 반영)** 버튼을 누릅니다.
- 위·장·간·폐 보스 처치 기록과 부산물 4종이 정상 획득 경로인 `GameManager.CollectRelic`을 통해 반영됩니다. 반복 클릭해도 이미 완료된 기록은 중복 처리하지 않습니다.
- 버튼은 현재 게임/저장 상태를 변경합니다. F8을 닫고 허브 중앙 포탈에 들어가면 최종보스 맵으로 이동합니다. 다른 맵에서 눌렀다면 먼저 허브로 귀환합니다.
- `FinalBoss.unity`를 단독으로 열어 Play해도 허브와 같은 플레이어·카메라를 생성합니다. 단독 미리보기 자체는 보스 처치 기록을 해금하지 않습니다.
- 최종 보스 방에는 걸어서 나가는 귀환 포털이 없습니다. 처치 후 확인창에서 메인 메뉴로 복귀할 수 있습니다.

## 기존 4개 맵 분석과 통합

위·장·간·폐 씬은 모두 `ProceduralMap.MapGenerator`와 `ProceduralBiomeBridge`를 사용합니다.
XZ 평면으로 회전한 Grid 아래 Tilemap 레이어에 지형을 렌더링하고,
`GridData/MapCell`에서 이동 가능 여부를 관리합니다. 플레이어는
`ProceduralTerrainMotor`를 통해 같은 데이터를 조회하며, 타일과 오브젝트는 청크 단위로 로드합니다.

최종보스 맵도 같은 구조를 사용합니다.

- `Grid → Base / Grass / Second Floor / Cliff Tilemap`
- `MapGenerator → AuthoredMapLayout → GridData/MapCell → 공통 청크 렌더링`
- `ProceduralBiomeBridge`: 공통 바이옴·카메라·청크 연결. 별도 최종보스용 BiomeConfig에는 일반 적과 중간보스 생성 규칙이 없습니다.
- `ProceduralTerrainMotor`: 기존 4개 맵과 동일한 스폰·이동 경로.
- `FinalBossArena`: 방 상태와 기둥·귀환 지점 참조만 담당합니다. 독립적인 UV 이동 판정과 PlayerController의 최종보스 전용 이동 분기를 제거했습니다.

최종보스 방은 48×38 고정 배치를 유지합니다. 기존 탐험 맵의 300×300 무작위 지형을 그대로 복제하지 않고,
공통 생성기에 선택적인 `AuthoredMapLayout` 자산을 추가해 보스방의 배치를 지정합니다.
기존 4개 씬은 이 자산을 사용하지 않아 원래의 절차적 생성 경로를 그대로 실행합니다.
고정 맵 이동에는 경로 중간도 검사하여 대시·넉백으로 기둥이나 벽을 넘어가지 못하게 합니다.

## 아트와 배치

방 전체 이미지를 붙인 Quad는 사용하지 않습니다. 원본의 두꺼운 곡선 벽·신경망·연결 조직을
유지한 `CerebrumEnvironment_v2.png`를 셀별 Sprite/Tile로 나눠 공통 MapGenerator의
청크 로딩·해제 경로로 렌더링합니다. `AuthoredMapLayout.environmentAtlas`가 없는 기존 맵은
원래의 반복 타일 렌더링을 유지합니다. 시각용 벽 그림과 이동 판정은 분리되어 있습니다.
네 장기 기둥과 잠든 대뇌는 원본 텍스처를 참조하는 개별 SpriteRenderer와 윤곽 메시입니다.
원본 이미지는 보존했고, 내장 image_gen으로 장기만 제거한 배경 자산을 별도 생성했습니다.
생성 프롬프트는 `Art/Concepts/FinalBoss/CerebrumEnvironment_v2_prompt.md`에 기록했습니다.
기둥은 Billboard와 SpriteYSort를 사용하고, 바닥 점유 영역은 레이아웃 자산에서 지정합니다.
`SpriteOutline`이 씬에 저장된 윤곽 좌표로 표시용 Sprite 메시를 재구성하므로,
Unity에서 Sprite 자산을 다시 가져오거나 씬을 재실행해도 사각형 배경으로 돌아가지 않습니다.
최종보스용 BiomeConfig의 `spawnWorldItems`는 꺼져 있어 일반 아이템 상자를 자동 생성하지 않습니다.
기존 네 장기 맵의 기본값은 켜짐으로 유지됩니다.
대뇌와 기둥의 전투·파괴·세 페이즈 및 승리 확인창이 연결되어 있습니다.

## 편집과 검증

- `FinalBossLayout.asset`: 방 크기, 스폰 셀, 외곽 다각형, 기둥/대뇌 점유 영역.
- 맵은 48×62칸이며 기존 48×38 보스방은 북쪽으로 24칸 이동했습니다. `environmentAtlasArea`로 원본 그림의 비율을 유지하고, `approachArea`는 공통 바닥·절벽 타일로 렌더링합니다. 공격·소환·3페이즈 붕괴 범위는 통로를 제외한 보스방 좌표를 사용합니다.
- **Apply Approved Towers and Straight Approach**: 기존 씬의 나머지 구성을 유지하며 승인된 네 타워와 직선 통로를 적용합니다. 반복 실행해도 방을 중복 이동하지 않습니다.
- 타워 프레임 준비: `python3 Tools/BuildFinalBossPillarSprites.py`. 승인된 `Assets/_Project/Art/Generated/FinalBoss/ApprovedTowerDestruction/*-break-sheet.png`에서 256×384 투명 스프라이트를 추출하며, 한 타워의 모든 프레임은 동일 축척과 바닥 기준점을 사용합니다. Unity는 Point/no mip/uncompressed/60 PPU로 가져옵니다.
- `FinalBossBiomeConfig.asset`: 공통 바이옴 연결 설정.
- `FinalBossSceneBuilder.cs`: 씬·개별 Sprite 자산·허브 기반 대체 플레이어/카메라 생성.
- **Update Existing Prop Outlines**: 기존 씬의 배치를 유지하며 기둥·대뇌 윤곽과 자동 아이템 생성 설정만 갱신합니다.
- **Tools > Necrocis > Final Boss > Build Exploration Scene**: 최종보스 씬을 닫은 상태에서 재생성합니다. 생성 씬과 관련 자산의 수동 편집을 덮어쓰므로 레이아웃 변경을 유지하려면 빌더도 함께 수정해야 합니다.
- **Run Exploration Smoke Test**: 임시 저장으로 15종 미완료 조합의 잠금, 실제 F8 버튼 콜백, 4/4 기록, 허브 입장, 공통 지형 연결, 바닥 연결성, 기둥/벽 경로 차단, 이동 및 귀환 후 기록을 검증합니다.
- **Run Direct Scene Smoke Test**: 단독 씬 시작과 스폰·공통 지형 연결·이동·귀환·처치 기록 비변경을 검증합니다.
- **Verify Existing Organ Maps**: 기존 4개 맵의 300×300 생성, 안전한 스폰, 일반 아이템 생성 옵션 유지를 확인합니다. 검사할 장기 씬을 닫고 실행합니다.
- 테스트 결과와 카메라 캡처: `Logs/FinalBossSmoke/`.

## 최종보스 1페이즈

- 1페이즈에도 맵 상단의 최종보스 모습은 어둡고 잠든 상태로 표시하지만, `EnemyController` 전투 대상은 부여하지 않아 공격할 수 없습니다.
- 네 바이옴 기둥은 배경 픽셀이 없는 독립 투명 스프라이트와 기존 `EnemyController` 피해 처리 경로를 사용합니다. 각 기둥은 체력 65, 바이옴 색상의 월드 체력바, 기둥 실루엣에만 적용되는 밝은 피격 플래시와 짧은 흔들림/팽창 반응을 가집니다.
- 기둥이 남아 있는 네 바이옴은 일반 적을 계속 보충합니다. 기둥을 파괴하면 해당 바이옴의 일반 적 보충만 영구 중단됩니다.
- 기둥 파괴 시 대응 바이옴의 중간보스가 소환됩니다. 기본 설정은 장기 보스의 유효 크기를 유지하고 정의의 기본 체력·공격력·접촉 피해에 33%를 적용하며, 경험치·유물 보상은 없습니다. 크기와 약화 배율은 최종 보스 전용 설정에서 편집합니다.
- 승인 디자인은 위·장 v2, 알을 제거한 간 수정본, 폐 v2입니다. 파괴 시 위는 기포 파열·조직 주저앉음, 장은 수관 꺾임·포자 흩어짐, 간은 나무 분열·지층 낙하, 폐는 공기주머니 수축·석주 붕괴의 5개 파괴 프레임을 재생한 뒤 잔해를 유지합니다. 타워별 재생 시간은 각각 0.72/1.04/0.92/1.10초입니다. 피해 대상과 맵 충돌은 처치 즉시 해제합니다.
- 네 기둥을 모두 파괴한 경우에만 2페이즈로 전환하고 상단 최종보스의 원래 밝기를 복구해 활성화 상태를 표현합니다.

## 최종보스 전투 연출 보강 (2026-10-04)

- 1페이즈 하단 UI의 네 칸은 각 장기의 이름·고유 색상·현재 기둥 체력을 표시합니다. 기둥과 대뇌 사이의 가는 신경 연결선은 파괴 시 사라집니다.
- 잠든 대뇌는 천천히 호흡하며, 봉인이 줄어들수록 밝아지고 호흡이 빨라집니다. 장기별 증원은 대응 기둥 주변의 유효 지형을 우선 사용하고 플레이어와 안전거리를 유지합니다.
- 봉인 파괴 후 일반 증원은 최소 2초 동안 쉽니다. 마지막 봉인 처치 시 일반 증원과 1페이즈 적을 정리하고, 네 타워의 파괴 모션이 모두 끝난 뒤 0.15초 후 2페이즈로 전환합니다. 전환 시 추적 중인 적의 발사체도 회수합니다.
- 2페이즈는 전기 장판·유도 세포·낙하 폭탄·반면 촉수·반사 보호막·세포 탄막의 여섯 패턴을 사용합니다. 세포 탄막 기본값은 24발씩 3회이며 직진합니다.
- 2페이즈 UI는 체력과 패턴/전투 상태만 표시하며, 패턴별 회피 안내와 시간 막대는 표시하지 않습니다. 반사와 촉수 후에는 최소 2.1초의 공격 기회가 있고, 발사체 패턴은 남은 세포가 사라진 후 다음 패턴으로 넘어갑니다.
- 체력 50% 이하에서는 한 번의 신경 과부하 안내·포효가 발생하고 대뇌의 호흡이 빨라집니다. 공격 간격은 체력에 따라 단축되지만 예고 시간은 유지됩니다.
- 유도탄은 분홍색, 직진 탄막은 황금빛으로 구분합니다. 움직이는 플레이어와 탄환 사이의 프레임 구간을 검사하여 저프레임 관통을 줄이고, 소멸 중인 흐릿한 탄환은 피해를 주지 않습니다.
- 플레이어 주변 유도 경고 원과 탄환·반사 피격 원은 생성하지 않습니다. 피격 반응은 기존 플레이어 피해 처리 경로를 사용합니다.
- 보스 처치 시 공격을 즉시 정리하고, 대뇌가 수축하며 어두워지는 연출과 3초간의 처치 안내를 표시합니다. 기존 보스 효과음을 패턴·전환·처치 시점에 연결합니다.

검증: 런타임/에디터 C# 빌드, 실제 투사체 거리 함수의 8개 회귀 사례(프레임 사이 관통, 근접 빗나감, 정지, 반대 방향, 플레이어 교차, 높이 차이 등)를 확인했습니다. Unity 플레이에서 연출 배치·음량·전투 난이도는 별도 확인이 필요합니다.

## 최종보스 3페이즈: 분리와 추적 이동

- 전체 체력 40% 이하에서 남은 체력을 유지한 채 3페이즈로 전환합니다. 전환 전 단일 초대형 공격으로 체력이 0이 되는 예외만 40%로 보호하여 페이즈를 건너뛰지 않습니다. 최종 처치 기록은 3페이즈 체력을 모두 소진했을 때 저장합니다.
- 2페이즈의 발사체·장판·촉수·반사 연출을 정리하고, 대뇌가 차지하던 고정 충돌 영역을 해제합니다.
- `FinalBossPhaseThreeController`가 대뇌와 피격 대상을 하나의 이동 루트에 연결합니다. 1.8초 동안 전장 안으로 분리되어 내려오며, 새 투명 아트 `Resources/FinalBoss/PhaseThree/MobileCerebrum.png`로 변합니다. 기존 맵 조각의 윤곽 컴포넌트를 해제한 뒤 전용 스프라이트로 교체합니다. 분리 중에는 피해를 받지 않습니다.
- 이전 `CerebrumBoss.png`의 RGB 이미지와 전용 배경 제거 머티리얼은 폴백으로 보존합니다. 현재 사용하는 새 본체는 실제 알파 투명 PNG여서 기본 Sprite 머티리얼을 사용합니다. 이동 판정과 피격 박스도 이동형 몸체에 맞춰 조정합니다.
- 이후 초당 3.1 월드 단위로 플레이어를 추적하고 3.2 단위 거리에서 멈춥니다. 공통 맵의 이동 판정과 실제 이동형 몸체 크기를 사용하여 벽 통과를 방지합니다. 일시정지·플레이어 사망·보스 사망 시 이동을 멈춥니다.
- 3페이즈 전용 공격 6종과 10% 타임어택이 연결되어 있습니다. 현재 사용되는 새 투명 아트와 공격 사양은 [FinalBossPhaseThree.md](FinalBossPhaseThree.md)를 참고하세요. 기존 `CerebrumBoss.png`와 배경 제거 머티리얼은 대체 아트 누락 시의 폴백으로 보존합니다.
- 검증: 런타임/에디터 빌드 및 현재 공격·축소 경계·추적 계산 10개 검사를 통과했습니다. 기존 탐험 스모크 검사를 새 40% 전환과 모바일 이미지에 맞춰 갱신했습니다. 이번 작업에서는 Unity 플레이 스모크 검사를 실행하지 않았습니다.


## 최종 보스 전용 밸런스 편집

Unity 메뉴 `Necrocis → Balance → Open Final Boss Balance`에서
`Assets/_Project/Resources/Balance/FinalBoss/FinalBossBalanceConfig.asset`을 엽니다.

- `phaseOne`: 기둥 체력, 소환 간격, 공통몹 수, 바이옴별 종류·개체 수, 약화 중간보스 비율.
- `phaseTwo`: 본체 체력, 3페이즈 전환 체력 비율, 여섯 패턴의 피해·예고·재사용 간격과 탄환 수.
- `phaseThree`: 추적 속도, 회복 간격, 축소 경계 시간·시작 체력 비율, 돌진·잡기·촉수·낙하·경계 피해.
- `normal` / `hard`: 최종 보스 전투의 체력·피해·소환몹 속도·공격 대기·경험치 배율.

예를 들어 Hard 본체와 소환몹의 체력을 20% 올리려면 이 에셋의 `hard.health`를 `1.2`로 변경합니다.
일반 바이옴의 난이도 프로필과 진행도는 최종 보스 전투에 중복 적용되지 않습니다.
소환몹의 기본값은 해당 `MonsterDefinition`을 읽고 최종 보스 전용 배율만 적용합니다.
약화 중간보스는 정의의 기본값을 읽되 약화 배율을 추가하고 경험치 보상을 0으로 고정합니다.

전용 에셋은 방에 진입할 때 복사되고 소환 수치는 개체 생성 시 확정됩니다. 편집 결과는 다음 전투부터 확인합니다.
최종 보스의 몸통·팔다리 콜라이더, 유도탄 이동과 명중 반경은 이번 통합에서 변경하지 않았습니다.
기존 일반몹의 공격 중 콜라이더 확대 설정도 유지했습니다. 잡기 중에는 기본 공격·직업 스킬·이동 입력을 받지 않습니다.

생성 도구는 YAML 항목 순서 대신 Unity 직렬화 API를 사용합니다.
`Configure Biome Normal Enemies` 메뉴 또는 `Tools/ConfigureBiomeEnemies.ps1`을 실행하면
기존 몬스터와 밸런스 정의를 보존하면서 신규 일반몹 12종의 연결을 갱신합니다.
정의의 기존 튜닝 값을 기본값으로 덮어쓰지 않습니다.

통합 검증 순서:

1. `Necrocis → Balance → Verify Main Integration`: 일반몹·엘리트 공존, 정의 연결, 생성 도구 재실행과 최종 보스 설정 독립성.
2. `Tools → Necrocis → Final Boss → Run Exploration Smoke Test`: 허브 진입과 반복 보충·약화 소환 및 잡기 중 입력 차단.
3. 저장·밸런스·엘리트 배치 스모크 검사: 버전 1 저장 호환, Normal/Hard 및 같은 런의 배치·처치 기록.

검증은 임시 저장 폴더를 사용합니다. 과거 제작 단계의 “간 일반몹 0종”·“위 엘리트 미등록” 조건은
제작 에셋 대신 임시 설정 또는 원본 개수 스냅샷으로 확인합니다.

- 최종보스 씬을 단독 실행하면 허브의 영속 탄환 풀이 없던 문제를 수정했습니다. `GameInitializer.projectilePoolPrefab`이 허브와 동일한 탄환 설정의 프리팹을 생성하며, 허브에서 넘어온 기존 풀이 있으면 재사용합니다.
