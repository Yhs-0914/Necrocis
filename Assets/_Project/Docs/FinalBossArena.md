# 최종보스 맵 — 이동 테스트 버전

## 실행

- 일반 진행: Hub에서 장·간·위·폐 보스의 보상을 모두 획득한 후 중앙 최종보스 포탈에 접촉한다. 한 번 접촉하면 활성화와 씬 이동이 함께 일어난다.
- 맵만 바로 확인: `Assets/_Project/Scenes/FinalBoss.unity`를 열고 Play한다. 허브와 같은 플레이어 애니메이션·스탯·카메라 설정을 사용하는 폴백 프리팹이 플레이어가 없을 때만 생성된다. 이 미리보기는 보스 처치 기록을 해금하지 않는다.
- 방 아래쪽의 좁은 입구로 내려가면 Hub로 돌아온다. 입장 지점은 귀환 트리거와 떨어져 있어 들어오자마자 되돌아가지 않는다.
- 기존 이동·대시·마우스 휠 줌 조작을 그대로 사용한다.

## 현재 구성

- 맵 크기: X 48 × Z 38 월드 유닛. 기존 32×32 보스방보다 넓다. 45도 카메라 투영에서 약 16:9가 되어 승인된 시안의 비율을 유지한다.
- 승인된 `arena-phase1-dormant-boss.png`를 Unity 텍스처로 가져와 배경으로 사용한다. 대뇌는 상단에 붙어 잠든 모습이다.
- 바닥과 외곽, 대뇌 받침, 위·장·간·폐 기둥 네 곳에 대응하는 이동 제한 및 3D 콜라이더를 둔다. 이동 경로 전체와 기존 플레이어 발판 크기를 검사하므로 대시로 장애물을 넘지 못한다. 대각선 이동 중에는 가능한 축을 따라 미끄러진다.
- 카메라는 기존 추적/줌을 유지하면서 맵 밖 빈 공간이 드러나지 않도록 이동 범위를 제한한다.
- 보스 AI, 피격, 기둥 파괴, 적 소환, 페이즈 전환, 공격 패턴은 없다.
- 현재 그래픽은 통이미지이며 기둥·보스는 독립적으로 애니메이션/파괴되는 스프라이트가 아니다. 이후 전투 구현 시 레이어와 독립 오브젝트 아트를 분리한다. 현재 충돌 영역은 그림 전체를 예약하므로 그려진 기둥 뒤로 겹쳐 걷지 않는다.
- 최종보스방에서 저장하고 재개하면 Hub로 돌아오며 보스 4개 처치 기록과 플레이어 성장은 유지된다. 아직 없는 최종전 진행 상태를 저장한 것처럼 처리하지 않는다.

## 파일과 검증

- `FinalBossArena.cs`: 크기, UV 기준 이동 영역, 기둥 영역, 스폰, 카메라 제한.
- `FinalBossSceneBuilder.cs`: 승인된 아트, 실제 Hub 플레이어/카메라 설정을 사용해 씬과 폴백 프리팹을 생성한다. Build Settings에도 등록한다.
- `SceneLoader.LoadFinalBoss`: 로드 시점에 네 보상과 중복 로딩 여부를 재확인한다.
- `Tools > Necrocis > Final Boss > Run Exploration Smoke Test`: 별도 임시 세이브로 미완료 15조합 잠금, 실제 허브 진입 트리거, 스폰, 바닥 연결성, 기둥/벽 경로 충돌, 실제 플레이어 이동, 귀환 트리거와 처치 기록 유지를 검사한다. 실행 전에 열려 있는 씬을 저장한다. 테스트 후 원래 씬 구성과 Play Mode 설정을 복원한다.
- `Run Direct Scene Smoke Test`: FinalBoss 씬 단독 Play의 폴백 생성, 표시, 이동, 귀환과 처치 기록 비변경을 확인한다.
- 결과와 실제 Unity 카메라 캡처: `Exports/FinalBossConcepts/2026-09-25/Implementation/`.
- `Build Exploration Scene` 메뉴는 맵을 재생성한다. FinalBoss 씬을 닫은 상태에서 사용한다. 이 작업은 해당 씬과 폴백 프리팹의 수동 편집을 대체한다.

기존 세이브를 바꾸어 보스 4개를 강제로 해금하지 않았다. 정상 포탈 경로와 직접 씬 미리보기는 각각 검증한다.
